1. О ЧЁМ ИГРА
-------------
Rogue-like про дегустатора при дворе (средневековый сеттинг: король, казначей,
бабка, слуга и т.д.). На столе лежат блюда, часть из них отравлена или заражена.
Игрок берёт блюдо в руки (3D-осмотр "как в Skyrim"), выбирает чувства
(вкус / зрение / осязание / обоняние / слух) и конкретное действие
(лизнуть, понюхать, прищуриться...). Неверный способ проверки наносит урон
органам чувств. За раунд начисляются очки, опыт и репутация. Между забегами
есть магазин (свитки открывают новые действия, расходники, экипировка).

Структура игры:
  - сессия = несколько волн (GameManager.totalWaves, по умолчанию 3);
  - волна = случайный набор блюд на столе -> осмотр -> кнопка "Проверить" ->
    окно итогов -> следующая волна;
  - после последней волны - EndSessionWidget с кнопками Continue / Shop.

Сторонние ассеты и пакеты: DOTween (анимации), BayatGames SaveGameFree
(сохранения), Outline (OutlineFx), FronkonGames Retro Noir, PSX-постпроцесс
(Psx.Volume в сцене), TextMeshPro, Unity Input System, Unity AI Assistant /
Inference (пакеты com.unity.ai.*).

4. АРХИТЕКТУРА: КАК ВСЁ СВЯЗАНО
-------------------------------
Все игровые типы в namespace Degustation (кроме нескольких "корневых" скриптов
без namespace: LevelManager, FoodEnchanter, FoodTable, FoodList, FoodInstance,
TableLine, Dish, SlidePanel, FoodInspectionChoice, PlayerScore и др.).

4.1 Данные (ScriptableObject)
  FoodData          блюдо: foodName, shopIcon, prefab3D, placementOffset,
                    targetSense (каким чувством проверять), effectProfile
                    (FoodEffect), correctAction (SubActionData),
                    списки биомов/уровней (FoodBiom). Метод Roll() создаёт
                    RuntimeFood: для каждого яда силу 1-5, для каждой болезни 1-3.
  FoodEffect        списки ядов (PoisonType), болезней (DiseaseType),
                    affectedSenses, связанные расходники / экипировка.
  SubActionData     суб-действие (senseType, actionId, unlockType: Starter/Scroll).
  InspectionDamageTable  правила "эффект x способ проверки -> орган -> урон"
                    (baseDamage + strength * multiplier). Умеет ApplyDamage().
  SenseStatsData    HP шести органов (глаза, рот, осязание, нос, уши, желудок),
                    состояния по порогам HP, спрайты состояний, события урона,
                    Save/Load через SaveGameFree.
  InspectionPoints  очки осмотра на сессию (базово 5), Spend/Refund/AddBonus.
  PlayerScore       деньги, репутация, XP, уровни, события, Save/Load.
  ShopInventory     каталог магазина (категории, цены, TryBuy, скидочная карта).
  NPCWallet         кошелёк NPC: выплата игроку зависит от репутации.
  NPcCharacter      спрайты эмоций + реплики + особые блюда NPC.
  LevelType (нов.)  levelName, availableFood, possibleModifiers.

4.2 Поток одной волны (3D-режим)
  GameManager (DontDestroyOnLoad, синглтон)
    - на sceneLoaded находит в сцене FoodSpawner3D, InspectionProcessor,
      EndOfRoundWindow и кнопки по ИМЕНИ (GameObject.Find: "ConfirmButton",
      "ContinueButton", "ShopButton", "EndSessionWidget")
    - StartSession -> StartWave -> FoodSpawner3D.SpawnRandomItems()
  FoodSpawner3D
    - берёт FoodPlacementPoint-ы (дети стола), перемешивает, ставит
      FoodData.prefab3D, вешает FoodItem, вызывает FoodData.Roll()
    - сортирует блюда слева направо в системе координат камеры
  PlayerInteractor (на камере) - луч в курсор, ЛКМ по IInteractable
  FoodItem : IInteractable - подсветка (FoodHighlight через MaterialPropertyBlock),
    состояния OnTable / Moving / Inspected, сам достраивает коллайдер
  InspectionController (синглтон, DOTween)
    - блюдо летит в HoldAnchor перед камерой, включается Manipulation
      (вращение по осям камеры + зум с клампом, ввод из GameInput ->
      карта ControllOf3dObj), открывается SlidePanel.Open(food)
    - ПКМ / Esc возвращают блюдо на стол; на время осмотра выключаются
      скрипты игрока (disableWhileInspecting)
  SlidePanel + SenseRow - выбор чувств (toggle) и действий (dropdown) для
    каждого блюда, хранит FoodInspectionChoice; тратит InspectionPoints;
    список действий берётся из ActionUnlockManager
  Кнопка "Проверить" -> GameManager.OnConfirmPressed -> InspectionProcessor.ProcessAll():
    Perfect (верные чувство + действие): +20, урона нет
    Partial (верное чувство, неверное действие): +10, урон по targetSense
    Fail (чувство неверное или не выбрано): 0, урон по Taste (GetWorstSense)
    Урон считается по УЖЕ брошенному RuntimeFood блюда -> InspectionDamageTable
    -> SenseStatsData.TakeDamage
  GameManager: XP += сумма очков, репутация +1 при очках > 0, playerScore.Save(),
    EndOfRoundWindow.Show(...) -> следующая волна или EndSession.
  OrganView (2D UI) подписывается на события SenseStatsData и меняет спрайт органа.

4.3 Магазин и прогресс
  ShopInventory.TryBuy -> PlayerScore.SpendMoney; ScrollItemData.unlocksAction ->
  ActionUnlockManager.UnlockViaScroll (Save/Load через SaveGameFree).
  ShopItemView / InventoryItemView - UI-карточки. SceneSwitcher / SceneButton -
  переходы между сценами по имени.

4.4 Новая подсистема "план раунда" (в разработке, не закоммичена)
  LevelType (SO) -> LevelManager.RunRound(RoundPlan) -> FoodEnchanter.Apply(plan)
  -> FoodTable.Serve(dishes, location). FoodList.GenerateList() - случайное меню
  из префабов. FoodInstance - обёртка FoodData + модификаторы. Это каркас с
  пустыми методами-заглушками; со старым FoodSpawner3D / GameManager не связан.

4.5 Редакторские утилиты
  Degustator3DPrefabFactory: меню Degustation -> 3D -> Create Food Prefab Template /
  Create Placement Points (5 in a row) / Setup Inspection Rig (создаёт HoldAnchor
  и InspectionController).

4.6 Сцена SampleScene
  Объекты: PointStart, PointEnd, Tabel (стол), Main Camera, Directional Light,
  DishesManager (TableLine1), PlaceForDishes (TableLine), Gizmos, Psx.Volume.
  Из скриптов проекта на сцене только TableLine и TableLine1. Это отдельный,
  ранний подход к раскладке блюд по линии стола. Он не связан с
  FoodSpawner3D / FoodPlacementPoint.
  Build Settings: только SampleScene. ShopScene и MainMenu (имена зашиты
  в GameManager и SceneSwitcher) в проекте не существуют.

     (только новый Input System). CircularSkillCheck и MashingMiniGame зовут
     Input.GetKeyDown(KeyCode.Space) -> InvalidOperationException каждый кадр.
     Нужно заменить на InputCompat.KeyDown (в нём пока нет пробела для

     пишут результат только в Debug.Log, GameManager о них ничего не знает.

Ошибки структуры / компиляции (вероятные):
  6. FoodTable лежит в файле FoodEnchanter.cs, а класс Dish (MonoBehaviour) - в
     TableLine.cs. Unity требует совпадения имени MonoBehaviour и файла, иначе
     их нельзя повесить на объект. Кроме того, глобальный класс Dish
     путается с DishData / файлом Dish.cs в Scripts/Data.
  7. FoodList.cs и LevelType.cs подключают NUnit.Framework (скорее всего
     добавлено IDE автоматически). Это тянет тестовую сборку в игровой код;
     в билде может не собраться. Лишний using UnityEngine.Rendering в FoodList.
  8. LevelManager.cs лежит в LevelType_Pref и ссылается на FoodEnchanter /
     FoodTable / RoundPlan; метод RunRound нигде не вызывается, PickRandom не
     используется, поля dishesPerRound / modifiersPerRound не читаются.
  9. FoodServant.cs закомментирован целиком и ссылается на несуществующие
     типы (FoodMenu, dish.sourceData) - мёртвый код.
  10. FoodEnchanter.Apply - цикл с пустым телом; Serve в FoodTable только
      yield return null. Модификаторы пока ни на что не влияют.
      FoodList.GenerateMenu() пустой, закомментированный LevelType().

Логические недочёты в рабочем коде:
  11. GetWorstSense всегда возвращает Taste. Комментарий обещает "самый опасный
      способ", но реально нет анализа эффектов блюда.
  12. Возможен конфликт: InspectionPoints.OnEnable вызывает StartSession (SO

  14. GameManager ищет UI по имени (GameObject.Find) - хрупко; нет защиты, если

  15. SlidePanel.Start принудительно ставит панель в leftX; значения leftX /

  16. Слой "Inspect" не создан в TagManager (поле inspectLayerName пустое -

  17. Дубли и мусор: Menu.asset, NewFood.asset, NewFood 1.asset в корне,
